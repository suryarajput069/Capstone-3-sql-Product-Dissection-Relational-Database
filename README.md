# Capstone 3 - SQL Product Dissection & Relational Database Design 🛒

This repository contains a **Product Dissection and Relational Database Schema Design** case study, completed as part of the AlmaBetter PG Program in Machine Learning and AI Engineering (Capstone 3).

## 📌 Project Overview

The project involves dissecting a leading e-commerce platform, **Meesho**, to understand its core features and the real-world problems it solves. Based on this analysis, a relational database schema was designed to represent the platform's underlying data structure.

## 🎯 Objective

To research a leading platform's features and user experience, then translate those insights into a well-structured relational database schema (ER diagram) that reflects how the platform organizes and manages its data.

## 🛠️ Approach

1. **Platform Research** — Studied Meesho's core features, user journeys, and business model.
2. **Product Dissection** — Identified key functionalities and real-world problems solved by the platform.
3. **Case Study** — Analyzed specific user challenges and how Meesho's features address them.
4. **Schema Design** — Defined entities, attributes, and relationships based on the identified features.
5. **ER Diagram** — Created a visual Entity-Relationship diagram representing the schema.
6. **Rationale** — Documented the reasoning behind key design decisions.

## 🛠️ Tools & Technologies

- **SQL** — Relational database schema design
- **ER Diagram Tool** — Miro / similar platform for visual schema representation

## 📂 Repository Contents

| File/Folder | Description |
|---|---|
| `ER_Diagram/` | Entity-Relationship diagram files/images |
| `schema.sql` | SQL schema (tables, keys, relationships) |
| `case_study.pdf` / `.docx` | Written case study and rationale |
| `README.md` | Project documentation |

## 📈 Key Highlights

- Identified core entities such as Users, Sellers, Products, Orders, and Categories.
- Mapped relationships between entities based on real platform workflows.
- Designed a schema that supports scalability and reflects Meesho's business logic.
